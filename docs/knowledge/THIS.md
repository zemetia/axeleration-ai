## Do's

- Always read relevant blueprint section before planning any change
- Use `next/link` and `next/navigation` for all routing — this project is English-only, no i18n routing layer
- Keep components Server Components by default; add `'use client'` only when required
- Use design tokens exclusively for color — no raw hex/oklch/Tailwind palette utilities
- Every public page needs `buildMetadata()` + `<StructuredData>` — check `SEO_GEO_LLM.md`
- Follow the four-file rule for UI components: impl, stories, test, barrel
- Write compact, high-signal code — no unnecessary comments or abstractions
- Run `npm run lint` (must exit 0) before declaring any task done

---

## Don'ts

- Don't use `useState` for server data — TanStack Query only
- Don't call `fetch` or `apiClient` directly in components — always go through services
- Don't add root `proxy.ts` — use `src/middleware.ts` (export `middleware`) + `src/proxy/` modules instead
- Don't write raw hex colors, oklch values, or Tailwind color utilities in components
- Don't add error handling for impossible cases — only validate at system boundaries
- Don't create README or documentation files unless explicitly asked
- Don't use emojis unless the user explicitly requests them
- Don't summarize what was just done — the user can read the diff
- Don't statically import `@/ai/*`, `@/inngest/*`, `@/mcp/*` or `@/providers/register` from a `src/app/**/actions.ts` file — client hooks import those modules, so the bundler walks their whole graph. Use `await import()` inside the action body (enforced by `no-restricted-imports` in `eslint.config.mjs`)
- Don't call Server Actions from `useQuery` — actions are mutations only. Reads go through a GET route handler under `src/app/api/` or straight through a server component

- [2026-07-29] **Every stage in the Idea room can now be written by hand, not just generated** — research summary + findings (add/edit/delete), the idea text, and the script (logline + add/edit/delete beats). Three rules make manual and AI authoring equal citizens. (1) All manual edits go through one private writer, `writeStageOutput()` in `episode.service.ts`, which owns the status rule: PENDING/FAILED → READY so Approve turns on, APPROVED stays APPROVED, and a stage currently `GENERATING` is refused outright (a node's `completeStage` would overwrite the text with no trace). SCRIPT overrides it with `nextScriptStatus` — a logline with zero beats stays PENDING, because approving it would hand `scenesNode` an empty list. (2) **Approve would otherwise destroy manual text.** The graph is compiled with `interruptAfter: STAGE_ORDER`, so a thread parked at `next=['IDEA']` re-runs `ideaNode` on the next Approve. `alignCheckpointAfterManualWrite()` (`src/ai/graph/manual-authoring.ts`) does `graph.updateState(config, values, kind)` so `next` advances *past* the hand-written stage — deliberately with no "does the thread exist" guard, because an episode written entirely by hand has no checkpoint at all and that is exactly the case that would restart from START. It bails only when a downstream stage already has output, where the `asNode` rewind would be destructive. (3) Nodes now prefer the DB over the checkpoint for their *inputs* (`scriptNode` → `episodeService.idea()`, `voiceNode` → `script()`, `ideaNode` → `research()`), extending what `scenesNode` already did — that is what carries an edit of an already-run stage into the next regenerate. Scene `index` is an identity, never a position: `removeSceneSpec` only renumbers while `prisma.scene.count() === 0`.

(4) **A grey `<Skeleton/>` is not a status.** `RunStatus` shows what is running, a live elapsed counter, progress against the forecast (capped at 95% — a forecast is a guess), and counted clips for the scene batch, with `RunningBanner` in the layout so a run follows the user between rooms. - [2026-07-29] Data-flow rule established after the "web sangat lambat" pass: **a client query hook must never be the first fetch of data the server component already had.** Three places were paying a full fetch-after-hydrate round trip (asset grid, episodes table, and the whole episode control room, where `ControlRail` + `StagePanel` + `ScriptPanel` + `ResearchPanel` all waited on one `useEpisodeStages` call). Two mechanisms now cover it: pass `initialData` when the consumer is a direct child (`EpisodesSection`), and wrap the subtree in `<HydrationBoundary state={dehydrateQueries([[key, data]])}>` when the consumer is deep in the tree (`src/lib/query-client.ts`). `dehydrateQueries` builds a throwaway client per call so nested boundaries don't re-serialise an ancestor's payload. Critical detail: the browser `QueryProvider` and the server prefetch must share one config (`makeQueryClient`) — a mismatched `staleTime` makes every hydrated query refetch on mount and silently undoes the whole thing. Also standardised: `refetchOnWindowFocus`/`refetchOnReconnect` are **off** (each refetch is a JWE session verify + DB round trip), and ownership checks that were `ownerOf()` then `get()` are now single-query `getForOwner()` — that pair was two sequential round trips on a path polled every 3s.
- [2026-07-30] **Per-scene and batch scene generation are one operation at two grains, and the checkpoint is what makes that hard.** Generating a single scene from its card (`regenerateEpisodeScene`) used to patch the `scenes` channel with `graph.updateState(..., asNode: 'SCENES')` unconditionally. On a thread parked at `next: ['SCENES']` — exactly where a user sits when they generate beats card by card before running the batch — that attribution advances `next` past SCENES, so the following "Generate all scenes" resumed straight into VOICE and the batch never ran. The `asNode` patch is only safe once the node has actually produced the channel (`current.scenes` non-empty); before that the `Scene` rows are the record and `scenesNode` must be the one to declare the stage finished. Generalised rule, extending the 2026-07-29 entry: **`asNode` may advance past a stage the user completed, never past a stage the user has only partly done.** The other half of the fix is that `scenesNode` now reads back READY `Scene` rows and skips them (`sceneScope: 'missing'`, the default; `'all'` is the explicit Regenerate-all nuke), so one-by-one and all-at-once compose instead of the batch re-paying for clips that already exist — which also means `completeStage` overwriting `costEstimate` had to add the reused rows' cost back in, or a gap-filling run erases what the per-scene `addStageCost` calls recorded.
- [2026-07-30] Provider credentials in this dev environment are **not** in a runnable state and no pipeline stage can execute: the only `ApiKey` row is `sumopod`, every project has `modelConfig: null` so all stages resolve to `aiConfig.defaults` (`anthropic` llmText, `wavespeed` textToVideo, `elevenlabs` tts, `replicate` music — none of which have a key or an env var), and the sumopod key itself now returns `401 Invalid proxy server token` from its LiteLLM proxy.
